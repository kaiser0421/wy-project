Start with **SSE, a PostgreSQL sequence assigned inside the seat transaction, and Redis Streams for replay**. The draft’s biggest problems are a relay cursor that can skip committed changes, a 10-second freshness claim the system cannot enforce, and a capacity estimate that budgets sends but barely considers bytes.

### 1. SSE vs WebSocket — Agree with the SSE lean

Use SSE for the seat map, import progress, and admin alerts. The server pushes updates and clients already use HTTP for mutations. Use same-origin session cookies and `Last-Event-ID` for reconnect. Disable nginx buffering and compression on stream routes, and test through nginx. Wire logout, disablement, and role changes to active-stream revocation across workers. Handshake-only authorization leaves an existing admin stream readable after revocation. [HTML SSE standard](https://html.spec.whatwg.org/multipage/server-sent-events.html), [nginx proxy documentation](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)

### 2. Sequence and snapshot — Disagree with the relay cursor and Redis snapshot

An older XID can allocate ID 101 after a newer XID allocated 100. Filtering by `xid < xmin` can expose 101 while 100 is ineligible. Advancing the ID cursor then loses 100. An unrelated long-running write transaction can also stall the horizon.

Use `event_feed(event_id PK, seq bigint)` and `seat_outbox(event_id, seq, changes, recorded_at, request_id, PRIMARY KEY(event_id,seq))`. Acquire the counter after seat mutations and validation, increment once per state-changing transaction, insert the outbox row, and commit immediately. Read seats and counter in one read-only `REPEATABLE READ` transaction. A 1–3 ms lock hold implies a theoretical 333–1,000 transactions/s per event. Measure lock wait and hold time before accepting it. If it bottlenecks, evaluate WAL-based CDC with a coordinated snapshot. Redis Lua prevents interleaving, but separate snapshot reads can tear, script errors can leave earlier writes applied, and rebuilding from current DB state requires an exact replay boundary. [PostgreSQL snapshots](https://www.postgresql.org/docs/16/functions-info.html), [Redis Lua API](https://redis.io/docs/latest/develop/interact/programmability/lua-api/)

### 3. Fan-out — Agree with Redis Streams

Use one independent `XREAD` cursor per API **process** for each active event, multiplexing where practical. A shared consumer group splits delivery across workers. Publish strictly in sequence using explicit IDs. After a crash between `XADD` and the DB checkpoint, verify the existing entry before advancing. On Redis state loss, rebuild the retained tail from PostgreSQL and force reconnect on a generation change. Pub/Sub loses updates during disconnects. `LISTEN/NOTIFY` is a useful polling wakeup. Core NATS has the same replay gap, and JetStream adds another service for a capability Streams already provides. At 1,000 entries/s, 10,000 entries buy roughly **10 seconds** of replay. [Redis Streams](https://redis.io/docs/latest/develop/data-types/stream/), [PostgreSQL NOTIFY](https://www.postgresql.org/docs/16/sql-notify.html)

### 4. Slow consumers — Disagree with the queue and freshness bound

At 10 frames/s, 256 queued frames represent 25.6 seconds of history. A send timeout can expire well after a browser falls behind because nginx and TCP can accept bytes the browser has yet to process. Start with four pending frames, 64 KiB total, or 500 ms oldest-frame age, whichever limit hits first. Abort and retry with jitter. Replay from the last applied cursor and use a PostgreSQL snapshot on gaps. Send a progress heartbeat every second with a recently sampled DB head and no SSE ID. Mark the map stale on disconnect, persistent cursor lag, or five seconds without valid progress, and recheck when the tab resumes. Recovery time is unbounded during an outage. Any seat may be wrong until recovery. PostgreSQL still decides whether a purchase succeeds.

### 5. Scenario B — Agree with batching, disagree that “20k sends/s” proves capacity

At 2,000 subscribers and 100 ms ticks, that is **20,000 writes/s total**, about 6,667 per process if evenly spread across three. At 300–1,000 changed seats/s and 40 bytes/change, payload alone is **24–80 MB/s** across clients, before framing, TLS, and nginx’s upstream traffic. Multiply by seats per transaction if your input rate counts transactions. At 50 changes/s it is only ~4 MB/s. Serialize once per process per tick. Send `{from_seq,to_seq,changes}` with `id=to_seq`, coalescing each seat to its final state within a contiguous range. Apply only ranges starting at `last_seq+1`. Resume by replaying from that cursor and join live delivery through the same ordered reader. Measure connection distribution, RSS, loop lag, and bytes/s. With HTTP/1.1 on both legs nginx carries roughly 4,000 sockets for 2,000 streams.

### 6. Metrics aggregation — Agree with mergeable histograms, disagree with replica wall time

Use monotonic durations and flush cadence per worker. Assign each contribution to its **first durable receipt second** on the collector clock. Deduplicate by `(boot_uuid, flush_no)` and persist that receipt second before acknowledging. Sum identical histogram buckets and their counts, then derive percentiles. A worker 20 seconds slow would lose its share from finalized event-time buckets with a two-second grace. Receipt-time charts avoid that clock error but show a dip and later spike if delivery stalls. Flag delayed and missing reporters. Sum per-worker stream gauges, expire after three seconds, and mark incomplete totals. Use nginx completion logs for short-request edge RPS, latency, and 5xx, and ASGI for route and business attribution. Exclude SSE lifetime from request latency and count stream opens separately. [nginx logging documentation](https://nginx.org/en/docs/http/ngx_http_log_module.html)

### 7. Batch persistence — Disagree with silent loss under normal failure

A 50,000-row RAM queue evaporates on `kill -9`. Spool access and service logs to a bounded persistent volume. Batch every 500 ms or 2,000 rows via `COPY` into staging, then insert idempotently by source record ID. Checkpoint the spool only after commit. At 5,000 records/s and 500 bytes each, ten minutes needs 1.5 GB before overhead. Alert before capacity and emit explicit loss counters and chart gaps on exhaustion. Keep seat events in PostgreSQL until archive commit, keyed by `(event_id,seq)`, with retention independent of Redis. Persist finalized metrics and completeness together.

### 8. Alerts — Agree with the state machine, disagree with the coverage

Start with edge 5xx >2% over 30s with ≥100 requests, oldest unpublished event >2s for 10s, any expired hold overdue >30s, and any telemetry drop. Add DB pool wait, missing workers, spool saturation, SSE resyncs, and payment/import stalls. Alert when a synthetic hold-to-payment flow fails twice, or when purchase conversion collapses while inventory is available. HTTP 200 can hide a broken purchase funnel. Persist alert transitions for replay and run an independent monitor heartbeat check.

### 9. Tracing and logs — Disagree with custom tracing

Keep nginx-generated `request_id` for the required lookup. Use OpenTelemetry and W3C `traceparent` across HTTP, outbox, callbacks, and jobs. Link batch spans to inputs and keep per-change correlation in server telemetry. Persist structured logs in daily PostgreSQL partitions indexed on `(request_id, ts, log_id)`. Include span IDs and causal links since clock skew can scramble timestamp ordering. Keep lookup independent of trace sampling. [OpenTelemetry messaging conventions](https://opentelemetry.io/docs/specs/semconv/messaging/messaging-spans/)

### 10. Load testing — Agree with k6, disagree with the workload and checks

Use k6 with pinned `xk6-sse` for B. For A, run the required 3,000 VUs for 60s with a synchronized opening burst, then a separate arrival-rate sweep reporting `dropped_iterations`. Break out expected conflicts and sold-out responses. For B, hold 2,000 streams, sweep 50/300/1,000 changed seats/s, throttle readers, and kill the relay after `XADD` but before checkpoint. Exercise Redis reset, reconnect storms, and exactly-once metric merging with one worker 20s slow. Outbox insert timestamps measure insert-to-receive, including pre-commit work. Report RPS, p50/p95/p99, error rate, sequence coverage, and convergence. After drain, compare reconstructed **seat state** with PostgreSQL, reconcile paid items and per-user caps, and deliberately break the oversell guard to prove the concurrent test catches it. [xk6-sse](https://github.com/phymbert/xk6-sse), [k6 dropped iterations](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/dropped-iterations/)

### 11. Front end — Agree with Canvas for rendering

Use Canvas with viewport culling, typed-array state, and one redraw per animation frame. Add a searchable, keyboard-operable DOM seat picker with accessible status text. Canvas alone makes seats inaccessible to keyboard and screen-reader users. Profile pan, zoom, selection, and burst updates at 10,000 seats and with a 100,000-seat import.
