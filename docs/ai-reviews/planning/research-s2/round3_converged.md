# Round 3 — converged position (please red-team)

## Push
- SSE `GET /api/v1/events/{id}/seat-stream` via nginx (HTTP/2 edge, `proxy_buffering off`, `proxy_read_timeout 1h`, `X-Accel-Buffering: no`, upstream `least_conn`, keepalive). Auth: access-token cookie OR `?ticket=` (30s single-use ticket from `POST /api/v1/stream-tickets`). Revocation: each process subscribes to Redis Pub/Sub `auth:revoked` (user_id/session_id) and closes matching streams; additionally re-validate session every 30s.
- In-tx counter: `UPDATE event_feed SET seq=seq+1 WHERE event_id=$1 RETURNING seq` as the LAST statement before COMMIT, only for txs that changed seat state; `INSERT INTO seat_outbox(event_id, seq, changes jsonb, request_id, recorded_at)`. Failed/no-op attempts never touch the counter. synchronous_commit=on. Measure counter wait p99 in Scenario A; CDC is documented as the alternative.
- Relay (2 containers, 1 active via `pg_try_advisory_lock` held on a dedicated session): wakeup by LISTEN/NOTIFY (`NOTIFY seat_outbox` in the tx) + 200ms poll fallback; per event reads `seq > checkpoint ORDER BY seq LIMIT 500`; requires contiguity (seq gaps impossible since counter is in-tx; a gap = bug → alert). `XADD seat:{gen}:{event_id} <seq>-0 MAXLEN ~ 20000 data <json>` (pipelined), then `UPDATE relay_checkpoint SET seq=...`. Crash-recovery per F3 (verify entry by ID before re-adding; XADD with an ID <= last ID errors, which is itself a dedupe signal).
- Redis generation: `SET stream:gen <uuid>` created by relay on startup if missing; stream keys scoped by gen; readers poll `stream:gen` every 1s (and on XREAD error) → on change: drop rings, close all SSE streams with retry jitter; relay rebuilds tail (last 20k seq per active event) from seat_outbox with original IDs before setting `stream:ready:{gen}`.
- Per API process: one reader task per active event (refcounted by local subscribers) with own cursor; builds 100ms ticks: coalesced `{from_seq,to_seq,changes:[[seat_id,status]...]}` encoded once (orjson) into a shared ring of 50 ticks + byte cap 2MB. Each connection: cursor + 1 in-flight write. Lagging client gets union of ring ticks since its cursor (coalesced again, contiguous); if cursor is older than ring → serve replay from Redis XRANGE; if older than Redis → `event: resync` + close? No — close immediately; client reconnects with Last-Event-ID → server sees not coverable → sends snapshot as first event.
- Snapshot: per-process single-flight cache refreshed ≤1/s, read in RR tx: `SELECT seq FROM event_feed` + seat statuses (packed as base64 2-bit array in seat-index order, 10k seats → 2.5KB raw, ~3.4KB base64). Then bridge seq+1.. from ring/Redis before live.
- SSE frames: `id: <to_seq>` / `event: delta|snapshot|progress|resync` / `data: {...}`. `progress` every 1s: `{head_seq, server_ts}` no id. Client marks map "stale" banner if no progress for 5s (client monotonic clock) or head_seq - applied_seq > 0 for > 3s.
- Client applies delta only if from_seq == applied+1 (or from_seq <= applied+1 <= to_seq since coalesced ranges carry final states → idempotent apply). Gap → close & reconnect with Last-Event-ID (custom: we use fetch-based SSE reader (e.g. @microsoft/fetch-event-source) to control headers & last id).
- Worst case staleness: normal ≤ ~100ms tick + relay ~10-50ms; degraded bounded by stale banner at 5s; outage unbounded but visible; purchase always re-validated in DB (409 SEAT_UNAVAILABLE).

- Load: writer scenario drives fixed seat-change rates 50/300/1000 changes/s; 2,000 subscribers via k6+xk6-sse (custom k6 image built in compose `loadtest` profile). Metrics: connect success, time-to-first-snapshot, delivery latency = recv_ts − relay `pub_ts` (same host clock) and recv − writer response ts; seq coverage (gaps/resyncs per client), final state hash vs PG; server: RSS, event-loop lag, bytes/s, per-process stream count.

## Monitoring (Q6)
- Edge source = nginx JSON access log (`$msec,$request_id,$status,$request_time,$upstream_response_time,$upstream_addr,$request_uri route?`) to a shared volume; `telemetry` collector container tails with offset checkpoint (committed with batch in PG) → per-second RPS / 4xx / 5xx / latency histogram keyed by nginx `$msec` (single clock → no skew) with 2s grace, late lines counted into `late` counter. Stream requests excluded from latency (location-specific log or `$upstream_http_content_type`).
- App source = per-process ASGI middleware (raw ASGI) + business counters + gauges (sse_active, db_pool_wait, loop_lag); every 1s push `{boot_uuid, flush_no, mono_interval, counters, hist buckets}` to Redis Stream `telemetry:app`; collector assigns receipt second (collector clock), dedup `(boot_uuid, flush_no)` in PG unique index; gauges expire 3s; completeness = processes reporting / expected.
- Histogram: fixed log-linear buckets, 1ms..30s, ~ 4 sub-buckets per power of 2 ≈ 60 buckets ( ≤ ~19% error); mergeable by sum. Percentile = bucket upper bound interpolation.
- Persist `metrics_1s(ts, source, scope, rps, err_4xx, err_5xx, p50,p95,p99, hist int[] , conns, completeness)`; daily partitions, 14d retention; 1-minute rollup.
- Trust: edge for user-visible RPS/latency/errors; app for attribution/business; DB for business truth (orders/seats). Divergence alert when |edge−app| > 10% for 30s.
- Clock skew 20s on one replica: no effect on edge chart; app series unaffected because receipt-time; logs: trace view orders by (ts) but shows per-service ordinal and skew warning (collector computes per-boot offset = receipt_ts − reported wall ts; alert if > 2s).

## Batch persistence

ON CONFLICT (source_file_id, offset) DO NOTHING` into partitioned `service_logs` / `access_logs`; checkpoint offset in same tx. Backpressure: if PG slow, collector lags (files are buffer); alert collector_lag_seconds > 10; if disk > 80% oldest rotated file dropped with loss counter.
