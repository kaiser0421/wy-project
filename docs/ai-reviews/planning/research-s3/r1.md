## Critical

1. **Drop the Redis authorization cache and revoke sessions on role change.** A request can read the old role from PostgreSQL, pause, then refill Redis after a successful `DEL`. Staleness can therefore outlast the claimed 30 seconds after revocation. Keep opaque sessions and validate against the PostgreSQL primary on every authenticated request. Revoke the current session on logout and all sessions on disable or role change, including promotion. Remove `auth_version` unless you enforce it. Measure p50/p95/p99, pool wait, and DB QPS across replicas during the booking load test. The 0.3 ms figure is an estimate. [Spec §6.1 and Q5](/Users/kaiser/workspace/wy_test/requirement.txt:163)

2. **Give revocation a precise boundary for live connections and in-flight writes.** Use the same-origin session cookie for WebSockets, require an exact browser `Origin`, and authorize each subscription and privileged message against its resource. Bind sockets to session IDs and send a close signal after logout, disable, or role change. Pub/sub can miss the signal, so check authoritative session state before dispatching protected data, batching checks across sockets if needed. Recheck SSE and protected downloads at their authorization boundary too. Document what happens to bytes already sent and requests already authorized. For sensitive writes that must stop at revocation, serialize the final authorization check with the mutation. A single-use WS ticket adds little here and still needs session binding and revocation. [OWASP WebSocket Security](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html)

3. **Make import cancellation and finalization one transactional decision.** A worker can pass the last heartbeat, then commit after the user is disabled or the event is published. Keep cancellation in both modes. In the final transaction, lock and recheck the actor’s current permission, event ownership or Admin authority, draft state, and job claim. Disablement and event publication, deletion, and zone edits must take the corresponding locks in a consistent order. Define the outcome by transaction order. If disablement commits first, zero seats are imported. If import commits first, its result stands. An Admin retry needs a fresh authorization check and separate audit attribution.

4. **Make a stale worker incapable of committing.** Keep PostgreSQL `SKIP LOCKED` for this workload. Claim in a short transaction, use the DB clock for leases and a new fencing token per attempt, and condition heartbeat, progress, finalization, and cleanup on that token. Scope staging by attempt. Commit seat writes, counters, durable errors, and terminal status together. Test a paused worker resuming after another worker takes over, and a kill immediately after commit. Use polling for recovery and `LISTEN/NOTIFY` as a wakeup. arq, Celery, and Dramatiq offer worker tooling, but a separate broker still needs reliable dispatch from PostgreSQL and fenced side effects. Give hold expiry an independent execution budget so imports and exports cannot delay it. [PostgreSQL locking](https://www.postgresql.org/docs/18/sql-select.html) · [PostgreSQL NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)

## High

5. **Honor file deduplication across modes and failures.** Make `(event_id, SHA-256 of original file bytes)` unique. Reuploads return the existing logical job, including failed or cancelled jobs. If the requested mode differs, return the existing job with its original mode clearly identified. An explicit retry for eligible failures creates a new attempt under that job. If you also accept `Idempotency-Key`, scope it to actor and endpoint/event, bind it to file digest and request parameters, and return `409` on mismatched reuse. Reauthorize before returning any existing job. Resolve deduplication before rejecting a *new* job for an active import or a published event. An unrelated active import deserves an explicit conflict response. [Spec §6.2](/Users/kaiser/workspace/wy_test/requirement.txt:79)

6. **Flag every member of a duplicate group.** The conservative reading of `重複…的列` is that every row sharing the canonical `(zone,row,number)` is erroneous. First-wins silently makes `skip_invalid` depend on file order. Define normalization once and apply it to staging and the seat uniqueness constraint. Validate existing seats under the final event lock. A silent `ON CONFLICT DO NOTHING` can turn `all_or_nothing` into a partial success or give `skip_invalid` false counts. Require every rejected row to have a reason. Persist errors before deleting staging. `UNLOGGED` staging can disappear on a DB crash. ## Security and failure cases to test
