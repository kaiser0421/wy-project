1. **A — Use PostgreSQL only.** A request can start *after* the revocation commits and still hit Redis before the tombstone or generation bump lands. If the writer dies in that gap, healthy Redis keeps serving the stale entry, so fallback never triggers. A delayed reader can also refill after a tombstone expires or is lost. Missing generations must force a DB read, and recreating a counter can accidentally match an old entry. AOF recovery or replica promotion can restore the old state, and `noeviction` can reject invalidation writes under memory pressure. The miss path also needs a way to know the user ID before querying PostgreSQL. Use one indexed read on the primary with a fresh statement snapshot and check active status, revocation and expiry. Measure pool wait, DB CPU and p99 at 3,000 VUs. [Redis replication](https://redis.io/docs/latest/operate/oss_and_stack/management/replication/) · [Redis eviction](https://redis.io/docs/latest/develop/reference/eviction/)

2. **B — Revoke on disable and every role change.** Live role reads do enforce demotion for fresh requests, but Q5 asks for immediate invalidation of existing credentials after a role change. Update the role or active flag and revoke sessions in the same transaction. Serialize session issuance with those changes on the user row, so a concurrent login cannot issue a session from stale user state. Require fresh login after either change. [OWASP session renewal](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

3. **C — Agree.** Return the existing job for the same event and digest, with its actual mode and `deduplicated: true`. Allow explicit attempts only after a terminal failure with zero committed seats. Reauthorize the caller and check draft status when admitting the attempt. Atomically enforce one active import per event, and use an idempotency key, retry cooldown and attempt cap to contain repeated 100k-row work. Keep input bytes and error reports available for the documented retry window, with reports scoped to each attempt.

4. **D — Materialize a bounded snapshot for every sort, including `created_at`.** A late commit with an earlier timestamp can appear after the cursor or fall behind it. Either outcome breaks the declared page-one membership. Immutable ordering also leaves mutable filters and deletions unresolved. Capture the ordered **list response fields** in one PostgreSQL statement, with ID as the tie-breaker. An ID-only snapshot cannot return a row deleted between pages. Store the result with a TTL and per-user quota, sign the cursor with snapshot ID, subject and position, and recheck current access before returning each page. If access to any row on that page has been withdrawn, invalidate the cursor. Expiry or eviction should return `410`, and queries over the cap should return an explicit refine-filters error. A timestamp-based history table has the same late-commit problem unless its visibility model accounts for commit order. [PostgreSQL snapshot semantics](https://www.postgresql.org/docs/16/transaction-iso.html)

5. **E — Agree as a measured starting point.** Use 19 MiB, two iterations and one lane. Four concurrent hashes consume about 76 MiB for Argon2 alone. Enforce the budget across processes in the container and across login, registration and rehashing. Reject excess work before submission with `503` and `Retry-After`, and hold the slot until the thread actually finishes, including after client cancellation. Benchmark the 30–60 ms target and cgroup peak alongside exports and normal traffic. [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

6. **F — Cookies everywhere, including k6 and Swagger.** Use `__Host-sid` with `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/` and no `Domain`. Use a session-bound CSRF header on unsafe requests. Document HTTPS for LAN access and reserve `COOKIE_SECURE=false` with `sid` for explicit development use. k6 can retain cookies per VU and send the CSRF header. A separate token endpoint adds credential issuance and revocation work without a demonstrated client need. [Cookie attributes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) · [k6 cookies](https://grafana.com/docs/k6/latest/using-k6/cookies/) · [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)

7. **F2 — Reject the five-second authorization window for authenticated streams.** A missed Pub/Sub close leaves a revoked socket eligible for subsequent updates. Batch distinct session IDs per replica immediately before each outbound batch, checking the session, active user and current subscription permission, including admin role where required. Bound batch size and queue time, discard queued frames on invalidation, and stop dispatch if PostgreSQL cannot validate. Use Pub/Sub to close promptly and validate the browser `Origin` at handshake. The dispatch check is the authorization point for frames already in flight. [OWASP WebSocket guidance](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html)

8. **G — Concrete outcomes.**
   - **G1.** Treat published-only Viewer browsing as an explicit visibility assumption. Keep Viewer sales-report access for all events under the literal spec, including empty draft reports. Import errors are owner/Admin only. Scope the job lookup by both event and job ID, and return `404` for a hidden draft or mismatched pair.
   - **G2.** Agree. Authorize the event before resolving dedupe, and use the event-scoped DB uniqueness constraint to arbitrate concurrent uploads.
   - **G3.** A valid HMAC protects the signed amount from tampering. Bind the callback to the stored payment attempt, order, amount and currency. Deduplicate by provider plus transaction ID and verify that a repeat matches the stored payment identity. Acknowledge exact repeats idempotently, reject conflicting reuse, and make the dedupe record and permitted order transition atomic. A nonce alone cannot prevent a second valid callback from applying the payment twice.
   - **G4.** Take the event lock for import admission, finalization and publication. I’d return `409` while an import is queued or running, so publish neither waits for the background job nor cancels it. Keep the draft-state recheck at finalization as a backstop.
