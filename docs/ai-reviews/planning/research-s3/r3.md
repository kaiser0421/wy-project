## 1. D — pagination

1. **The XID test works for retained inserts and soft deletes on the primary.** `pg_current_xact_id()` assigns a top-level `xid8` if needed and returns the same ID inside a savepoint. `pg_current_snapshot()` serializes the active statement snapshot without assigning an XID. `pg_visible_in_snapshot()` returns true below `xmin`, false at or above `xmax`, and true between them if the XID is absent from `xip`. It ignores commit status, so an aborted XID can return true. Use top-level markers persisted atomically with the changes they describe. Capture page 1 and its snapshot in one read-only statement or one repeatable-read transaction. [PostgreSQL 18 implementation](https://raw.githubusercontent.com/postgres/postgres/REL_18_STABLE/src/backend/utils/adt/xid8funcs.c)
2. **Cursor size and wraparound.** Snapshot text grows with the number of XIDs in `xip`, driven by concurrent XID-bearing transactions across the cluster and bounded by database concurrency, including prepared transactions. At 3,000 entries with 10-digit XIDs, expect about 33 KB raw and 44 KB base64url before cursor metadata. Measure actual `xip` and encoded sizes during load. `xid8` carries the epoch across 32-bit wraparound. Normal vacuum and freeze obligations still apply. Serialized snapshots neither pin old row versions nor prevent vacuum. [Snapshot encoding](https://raw.githubusercontent.com/postgres/postgres/REL_18_STABLE/src/backend/utils/adt/xid8funcs.c#L403), [transaction IDs](https://www.postgresql.org/docs/18/transaction-id.html), [vacuum](https://www.postgresql.org/docs/18/routine-vacuuming.html#VACUUM-FOR-WRAPAROUND)
3. **Use the primary.** PostgreSQL 18 rejects `pg_current_xact_id()` in recovery. A standby can call `pg_current_snapshot()`, but recovery puts known running XIDs in `subxip` while the SQL function serializes `xip`. A standby-generated token can therefore misclassify a transaction that was still running at capture. Evaluating a primary-generated token on a physical standby is possible once it has replayed through a primary WAL fence captured after page 1, on the same history, with required rows retained. Invalidate cursors after a history-changing failover or restore. [Snapshot implementation](https://raw.githubusercontent.com/postgres/postgres/REL_18_STABLE/src/backend/utils/adt/xid8funcs.c#L305), [recovery snapshot implementation](https://raw.githubusercontent.com/postgres/postgres/REL_18_STABLE/src/backend/storage/ipc/procarray.c#L2228), [WAL replay functions](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-RECOVERY-INFO)
4. **Take-home pick — materialize the narrow list projection in logged PostgreSQL.** Freeze membership, order and displayed list fields in one statement, then page by stored ordinal. Use a short signed cursor bound to the caller and query, a 10-minute TTL, and creation and storage quotas. This handles mutable title, category, status and sales dates with one path. A monotonic field can still cross a filter boundary. Choose **(a)** if measurements justify a second path for truly immutable queries. Choose **(b)** only if historical reads become a product requirement. [Platform spec](/Users/kaiser/workspace/wy_test/requirement.txt)

## 2. Top 10 remaining risks

1. **Oversell and quota races.** In one transaction, lock the user/event quota row and seats in a consistent order. Count live holds plus purchases against four, enforce a database uniqueness backstop for active allocation, and use DB time sampled after lock acquisition for expiration. Allocate in SQL. Test both seat contention and two different keys exceeding quota, then break the guard and show the test fails.
2. **Ambiguous retries and late payment.** Scope idempotency by user and operation, bind it to a payload digest, replay committed results, and define in-progress and mismatched-key responses. Commit a payment intent with the order, authenticate callbacks, dedupe provider event IDs, and serialize payment, cancellation and expiry on the order row. Reconcile late success with an idempotent refund or void. Validate the callback against the stored amount.
3. **Lost edits and event lifecycle races.** Use a row version with `If-Match` for edits. Make publish, import admission and finalization, deletion, and order admission share a compatible event-lock protocol. Recheck state and order existence under that lock. Keep price and fee fixed on the order.
4. **Unclaimable imports and stale workers.** Durably store the upload before exposing a claimable job. Sweep orphan blobs and enforce unique event/file digest. Use a renewable lease and verify its fence on progress, finalization and cleanup. Enforce 20 MB and 100,000 rows at the app, preserve source locations, and commit seats, errors and terminal state together. Test worker termination and the 100,000-row/60-second target.
5. **Revocation races and cookie-auth socket gaps.** Validate on the primary and serialize sensitive writes with revocation through commit. Check WebSocket Origin and resource authorization on subscribe, then revalidate on flush and heartbeat. Apply equivalent checks to long-lived SSE and admin streams. Bound send time, close on prolonged DB failure, and document that bytes already handed to transport can arrive after revocation.
6. **Lost or reordered live updates.** Persist seat events transactionally with seat changes. Use durable replay offsets and per-seat versions across API replicas. Treat notifications as wake-ups, disconnect slow clients with bounded queues, and recover from gaps with replay or a fresh snapshot plus watermark. Test reconnects and replica restarts with 2,000 sockets and measure convergence time. [PostgreSQL `NOTIFY`](https://www.postgresql.org/docs/18/sql-notify.html)
7. **Redis outage overwhelms PostgreSQL.** Keep login fail-closed and make limiter counter and expiry updates atomic. During booking degradation use a bounded per-instance admission budget, short pool-acquisition deadlines and fast overload responses. Apply the Argon2 memory/concurrency budget across all worker processes in each container.
8. **Pagination abuse or stale authorization.** Cap concurrent snapshot creation and retained bytes per caller and globally. Reject an over-budget query explicitly and return an explicit restart response on expiry. Recheck access on every page and invalidate affected snapshots when access changes. Silent 10k truncation violates the pagination contract.
9. **Export exhausts resources or leaks data.** Start with one export per 512 MB API instance plus a global cap. Bound transaction time and temp disk, release the database snapshot before download, reauthorize delivery, and sweep abandoned files. Write untrusted cells as literal text and omit buyer identifiers for Viewers or use event-scoped keyed pseudonyms. Measure 500,000 rows under the actual cgroup limit. [XlsxWriter workbook options](https://xlsxwriter.readthedocs.io/workbook.html)
10. **Healthy charts conceal failed bookings.** Use ingress-timed one-second buckets, merge histogram counts before computing percentiles, and dedupe durable batches by producer and sequence. Expose missing data and stale connection gauges. Alert on booking outcomes, callback backlog and replay lag. Redact secrets and buyer data from correlated logs.

## 3. Remaining disagreements

1. **D:** Use PostgreSQL materialization for the graded build. Keep raw `pg_snapshot` text out of cursors and avoid a version-history table for pagination alone.
2. **F2:** Per-frame primary validation is a reasonable check. Immediate credential invalidation applies to subsequent authorization decisions. Socket delivery needs an explicit in-flight race and a measured close deadline.
3. **Degraded booking:** Use bounded admission when Redis fails. An unrestricted fail-open path puts the primary’s booking and authorization traffic at risk together.
4. **Import and export:** Publish jobs only after upload durability. Use a keyed pseudonym or omit the buyer identifier. Set export concurrency from the 512 MB measurement.
