高併發搶票與即時監控平台：系統架構

PostgreSQL 是座位、訂單與配額的唯一真實來源；Redis 只負責投遞與限流，從不決定誰拿到座位。下圖是元件總覽，後面四張圖分別追蹤搶票、即時推送、付款與監控的資料流向。

元件總覽與資料流向

由上而下依信任邊界分層；右側為背景服務，經由共用通道存取資料層。圓形編號對應下方說明。

使用者端 邊界 應用服務 背景服務 資料層
  1. 1
    瀏覽器與壓測 → nginx
    HTTP(S)，session cookie + CSRF header。本機為 http://localhost:8080。
  2. 2
    nginx → api
    REST 與 SSE（least_conn）。nginx 產生 X-Request-ID，一路傳到所有服務的日誌。
  3. 3
    nginx → payment-mock
    買家開啟模擬付款頁 /pay/*。
  4. 4
    payment-mock → api 回呼
    HMAC 簽章，每次重送重新簽章，失敗重試 24 小時。
  5. 5
    api → payment-mock
    以同一個 merchant id 冪等建立付款意圖。
  6. 6
    api → PostgreSQL
    搶票單一短交易（鎖座位、寫訂單、寫 outbox）、session 驗證、報表快照讀取。
  7. 7
    api ⇄ Redis
    寫入：限流、每秒 histogram、撤銷 Pub/Sub。讀取：座位事件 Stream、撤銷通知、admin:feed。
  8. 8
    api → Volumes
    上傳暫存檔（fsync 後才建立 job）與 Excel 匯出檔。
  9. 9
    背景服務 ⇄ 資料層
    worker 以 SKIP LOCKED + lease + fence 處理 job；relay 在 PG 指派 seq、同交易寫入 seat_events，再依序 XADD 到 Redis；collector 讀 logs spool 與遙測、以 COPY 批次寫入 PG；migrate/seed 初始化資料庫。
  10. 10
    worker → payment-mock
    reconciler 每 15 秒輪詢沒有回呼的付款、執行退款與取消意圖。
所有服務都寫 JSON 日誌nginx、api、worker、relay、payment-mock 的日誌寫入 logs spool，collector 依 request_id 入庫，供 Admin 查詢單一請求的跨服務日誌。
告警的備援路徑collector 失聯時，api 自行把 MONITOR_DOWN 寫入 PostgreSQL 並推給 Admin；Redis 也掛時 Admin 頁改為輪詢。
Redis 不是真實來源Redis 被清空時，relay 以新 generation 從 PostgreSQL 的 replay log 重建 Stream，客戶端重新取快照。

搶票寫入路徑（防超賣）

一個請求從進入 API 到提交的完整路徑。保護從第 ⑤ 步鎖座位開始，到 COMMIT 釋放；第 ⑦ 步的 partial unique index 是最後一道防線。

sequenceDiagram
  autonumber
  participant C as 購票者
  participant N as nginx
  participant A as api
  participant P as PostgreSQL
  C->>N: POST /api/v1/events/{id}/orders（Idempotency-Key）
  N->>A: 加上 X-Request-ID
  A->>P: session 驗證（索引查詢）
  A->>P: BEGIN
  A->>P: ① 冪等 advisory try-lock，查既有結果
  A->>P: ② 活動閘門（已發布、開賣時窗）
  A->>P: ③ 配額 guarded UPDATE（reserved ≤ 4−n）
  A->>P: ④ INSERT orders 表頭
  A->>P: ⑤ 鎖座位 NOWAIT / SKIP LOCKED（保護開始）
  A->>P: ⑥ UPDATE seats WHERE status='available'（筆數須相符）
  A->>P: ⑦ INSERT order_items（partial unique index）
  A->>P: ⑧ 計價、expires_at、outbox、冪等回應
  A->>P: COMMIT（保護釋放）
  alt 成功或相同內容重送
    A-->>C: 201 Created
  else 座位被占、競爭、限購、未開賣
    A-->>C: 409 problem+json
  else 同 key 不同內容
    A-->>C: 422 problem+json
  else 鎖等待逾時
    A-->>C: 503 server-busy
  end

即時座位推送

順序由 PostgreSQL 保證：relay 先在資料庫提交連續 seq，再依序投遞到 Redis。每個座位帶 version，客戶端只套用較新的狀態，因此畫面不會倒退。

flowchart LR
  TX["訂票或釋放交易<br/>COMMIT（含 outbox 列）"] --> OB[("outbox<br/>seq IS NULL")]
  OB -->|"每 50ms 依 id 排序"| RL["outbox-relay<br/>1. 提交連續 seq + seat_events<br/>2. 依序投遞"]
  RL -->|"XADD seq-0"| RS[("Redis Stream<br/>seat:gen:event")]
  RS -->|"XREAD 連續性檢查"| RD["api 程序 reader<br/>100ms 合併、共享 ring"]
  RD -->|"SSE delta<br/>seat_idx, status, version"| CL["瀏覽器<br/>version 較大者勝"]
  CL -.->|"斷層時重連<br/>Last-Event-ID = 最後套用的 gen:seq"| RD
  RD -.->|"回補：ring → Redis → PG 已指派 outbox → 版本化快照"| PGR[("PostgreSQL<br/>replay log / 快照")]

付款與回呼

每筆訂單只有一個可扣款的 attempt。回呼在單一交易內去重、鎖訂單，期限前成交，期限後先歸還座位與配額、再建立退款。

sequenceDiagram
  autonumber
  participant C as 購票者
  participant A as api
  participant P as PostgreSQL
  participant M as payment-mock
  participant W as worker
  C->>A: POST /orders/{id}/payments
  A->>P: txn1：建立唯一 attempt，寫入 idempotency（in_progress）
  A->>M: 建立 intent（merchant id 冪等）
  A->>P: txn2：awaiting_customer，idempotency 完成
  A-->>C: checkout_url
  C->>M: 完成付款
  M->>A: 回呼（HMAC，失敗重試 24h）
  A->>P: 單一交易：去重、鎖訂單、在鎖內查 capture
  alt 期限前
    A->>P: paid，座位 held → sold
  else 期限後仍為 pending
    A->>P: release_order 歸還座位與配額，建立退款
  else 已過期、已取消或重複扣款
    A->>P: 只建立退款
  end
  W->>M: 每 15 秒輪詢未回呼的付款，執行退款

監控資料流

兩個來源：nginx 日誌代表使用者實際感受，應用層 histogram 負責歸因。多副本的數據以 collector 校準後的時間分桶，副本時鐘偏移不影響圖表。

flowchart LR
  NGL["nginx access log<br/>使用者實際感受"] --> SP[("logs spool")]
  APL["api、worker、payment-mock<br/>JSON logs（含 request_id）"] --> SP
  HIST["api middleware<br/>每秒 histogram、interval_no"] --> TS[("Redis telemetry")]
  SP --> COL["telemetry-collector"]
  TS --> COL
  STUB["nginx stub_status"] -->|"每秒"| COL
  COL -->|"COPY 與 checkpoint 同交易"| T1[("access_logs、service_logs<br/>metrics_1s、business_1s<br/>alert_events")]
  COL -->|"每秒評估告警"| FEED[("Redis admin:feed")]
  FEED --> SSEA["api → Admin SSE<br/>即時圖表與告警"]
  ADM["Admin"] -->|"GET /admin/requests/{id}/logs"| API2["api"]
  API2 -->|"依 request_id 查詢"| T1
  API2 -.->|"collector 失聯時直接寫告警"| T1
